# Разное (Логин и регистрация)

_Всего: 1 TestCases_

### Проверка целостности данных

*Тест-кейс* · Priority: Highest · Tags: ргеистрация, api

**Предусловия:**

1. Емейл не зарегистрирован в системе
   - Тестовые данные: Test_user@mail.ru

**Шаги:**

1. Отправить POST запрос `http://localhost:4000/auth/register`
Тело запроса (Body → raw → JSON):
`{"email": "admin@gmail.com", "password": "Password123"}`
   - Ожидаемый результат: Запрос успешно отправлен на сервер
2. Проверить код состояния ответа
   - Ожидаемый результат: HTTP Status: `201 Created`
3. Проверить тело ответа от сервера
   - Ожидаемый результат: Тело ответа в формате JSON:
`{"token": "string", "user": {"id": 0, "email": "string", "role": "string"}}`
4. Перейти на `http://localhost:5173/login`
   - Ожидаемый результат: Ресурс доступен, содержимое страницы отображается корректно
5. Войти в систему, используя емейл Test_user@mail.ru, пароль password5
   - Ожидаемый результат: Пользователь авторизован в системе и перенаправлен на страницу Дашборда
6. Изучить роль, отображаемую на странице Дашборда
   - Ожидаемый результат: Отображаема я роль соответствует значению “role”, полученному в шаге 1
7. Убедиться, что запись пользователя существует в БД, отправив запрос
SELECT * FROM users WHERE email = 'Test_user@mail.ru';
   - Ожидаемый результат: Запрос возвращает одну строку с информацией о `id`, `email`, `password_hash`, `role`, `created_at пользователя`
8. Изучить поле `email` в ответе БД
   - Ожидаемый результат: Значение совпадает с введенным при регистрации
9. Изучить поле , `password_hash в ответе БД`
   - Ожидаемый результат: Поле не пустое и не содержит пароля в открыток виде
10. Изучить поле `role в ответе БД`
   - Ожидаемый результат: Поле не пустое, роль соответствует соответствует значению “role”, полученному в шаге 1
