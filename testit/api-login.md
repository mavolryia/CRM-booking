### 200 Успешный вход с пробелом перед email

*Тест-кейс* · Priority: Medium · Tags: api

**Шаги:**

1. Отправить POST запрос `http://localhost:4000/auth/login`
Тело запроса (Body → raw → JSON):
`{"email": " admin@gmail.com", "password": "Password123"}`
   - Ожидаемый результат: Запрос успешно отправлен на сервер
2. Проверить код состояния ответа
   - Ожидаемый результат: HTTP Status: `200 OK`
3. Проверить тело ответа от сервера
   - Ожидаемый результат: Тело ответа в формате JSON:
`{"token": "string", "user": {"id": 0, "email": "string", "role": "string"}}`
4. Проверить соответствие данных в ответе отправленным данным
   - Ожидаемый результат: email в теле ответа совпадает с email, указанным в запросе (с учётом обрезки пробелов в начале/конце, если они были в запросе)

### Попытка входа (data-driven, 6 сценариев)

*Тест-кейс* · Priority: High · Tags: api

**Шаги:**

1. Отправить POST запрос `http://localhost:4000/auth/login`
Тело запроса (Body → raw → JSON):
`{"email": "%email", "password": "%password"}`
Сценарий %scenario. Значение "(пусто)" означает пустую строку ""
   - Ожидаемый результат: Запрос успешно отправлен на сервер
2. Проверить код состояния ответа
   - Ожидаемый результат: HTTP Status: `%expectedStatus`
3. Проверить тело ответа от сервера
   - Ожидаемый результат: Тело ответа в формате JSON:
`{"token": "string", "user": {"id": 0, "email": "string", "role": "string"}} (для 200) либо {"error": "string"} (для 400/401)`
4. Для сценария %scenario, где ожидается код 200 (1_valid_login), проверить соответствие данных в ответе отправленным данным
   - Ожидаемый результат: Для сценария 1_valid_login: email в теле ответа совпадает с отправленным %email. Для остальных сценариев (коды 400/401) шаг не применим — тело ответа не содержит email
