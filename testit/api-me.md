_Всего: 5 TestCases_

### 200 Получение пользователем собственных данных

*Тест-кейс* · Priority: Highest · Tags: api

**Шаги:**

1. Отправить GET запрос `http://localhost:4000/auth/me`
Тело запроса: отсутствует
Заголовок Authorization: Bearer <валидный токен>
   - Ожидаемый результат: Запрос успешно отправлен на сервер
2. Проверить код состояния ответа
   - Ожидаемый результат: HTTP Status: `200 OK`
3. Проверить тело ответа от сервера
   - Ожидаемый результат: Тело ответа в формате JSON:
`{"user": {"id": 0, "email": "string", "role": "string"}}`
4. Проверить соответствие данных в ответе
   - Ожидаемый результат: email в теле ответа совпадает с email пользователя, которому принадлежит переданный токен (владелец токена)

### 401 Отправка запроса с токеном в квери-параметрах URL

*Тест-кейс* · Priority: Medium · Tags: api

**Шаги:**

1. Отправить GET запрос `http://localhost:4000/auth/me?token=`
Тело запроса: отсутствует
Токен передан в query-параметре URL вместо заголовка Authorization; сам заголовок Authorization не передаётся
   - Ожидаемый результат: Запрос успешно отправлен на сервер
2. Проверить код состояния ответа
   - Ожидаемый результат: HTTP Status: `401 Unauthorized`
3. Проверить тело ответа от сервера
   - Ожидаемый результат: Тело ответа в формате JSON:
`{"error": "string"}`
