### 201 Отправка дополнительного поля role в теле запроса

*Тест-кейс* · Priority: High · Tags: api

**Шаги:**

1. Отправить POST запрос `http://localhost:4000/auth/register`
Тело запроса (Body → raw → JSON):
`{"email": "m.w.volkova0@gmail.com", "password": "Password1", "role": "admin"}`
   - Ожидаемый результат: Запрос успешно отправлен на сервер
2. Проверить код состояния ответа
   - Ожидаемый результат: HTTP Status: `201 Created`
3. Проверить тело ответа от сервера
   - Ожидаемый результат: Тело ответа в формате JSON:
`{"token": "string", "user": {"id": 0, "email": "string", "role": "string"}}`
Ожидается, что поле role из тела запроса игнорируется — роль присваивается только по правилу «первый пользователь = admin, остальные = manager», управлять ролью через API нельзя
4. Проверить соответствие данных в ответе отправленным данным
   - Ожидаемый результат: email в теле ответа совпадает с email, указанным в запросе (с учётом обрезки пробелов в начале/конце, если они были в запросе)
